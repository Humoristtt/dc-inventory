# Адаптивность интерфейса по доступному пространству

Статус: реализация в ветке `feature/responsive-device-layout`; production не меняется до отдельной приёмки.

Нормативная основа: `docs/FRONTEND_DESIGN_SYSTEM.md`. Цвета, градиент, радиусы, фирменная типографика, общие кнопки и `PageHeader` сохраняются.

## Принципы

- `@container` определяет компоновку по ширине содержимого страницы, а не по диагонали устройства. Если контейнерные запросы недоступны, остаются существующие `@media` и одноколоночный fallback для фильтров движения.
- `@media (pointer: coarse)` увеличивает области нажатия у компактных фильтров и иконок; основные кнопки по-прежнему используют общий контракт.
- Ширина shell ограничена прежним значением 1920 px. Документ больше не имеет принудительной минимальной ширины 320 px; карточки и текст должны переноситься без горизонтальной прокрутки.
- Для короткого desktop-окна уменьшается вертикальная навигационная панель вместе с резервом под неё. Safe-area и `dvh` учитываются при расчёте высоты редактора и фильтров.
- Новый `frontend/src/shared/ui/responsive.css` — дополнение к существующим shared primitives, а не альтернативная дизайн-система. Размеры и компоновка конкретных разделов принадлежат `*-responsive.css` соответствующих features. Их импорт централизован в `App.tsx`.

## Компоновка каталога

Ширина внутреннего контейнера: до 559 px — две колонки категорий; 560–999 px — три; от 1000 px — четыре. Список оборудования получает две колонки от 1160 px внутренней ширины. При недостатке места панель фильтров и сортировки переносится на новую строку.

## Приёмка

`cd frontend && npm run check:design-system && npm run lint && npm run typecheck && npm test && npm run build && npm run test:e2e`

`responsive-layout.spec.ts` проверяет ширины 320/390/600/768/1024/1280/1920/2560 px в Chromium и WebKit, отсутствие горизонтального overflow, резерв для нижней навигации, сенсорные размеры элементов фильтра и доступность footer диалога при высоте 420 px. Эти тесты не заменяют ручную проверку реальных Telegram Desktop, Android, iOS, tablet и desktop: в частности необходимо проверить появление экранной клавиатуры, системный zoom текста и границы safe-area.

До ручной приёмки запрещено объединять ветку с основной и выкатывать в production. Backend, schema, сетевое окружение, mutation gates и состав данных в этой работе не меняются.
