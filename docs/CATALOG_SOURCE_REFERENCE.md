# Историческая сверка исходных таблиц каталога — Stage 5

Этот файл сохраняет **проектные наблюдения Stage 5** по локальным примерам из `data/source/`. Он не задаёт текущую схему каталога, не является инструкцией по импорту и не подтверждает реальные складские остатки. Указанные тогда категории, поля и варианты импорта могли впоследствии измениться или быть удалены. Действующая схема определяется [`backend/app/modules/catalog/configuration.py`](../backend/app/modules/catalog/configuration.py) и [CATALOG_SCHEMA.md](CATALOG_SCHEMA.md), правила количества — [WAREHOUSE_DOMAIN.md](WAREHOUSE_DOMAIN.md).

Референсные таблицы остаются вне Git и не используются как источник production stock. Авторитетный источник первого наполнения был утверждён **позже**, отдельно от Stage 5: внешний операторский workbook с валидатором `backend/app/bootstrap/inventory_workbook.py` и защищённым однократным CLI `backend/app/bootstrap/production_inventory.py`. Первоначальный импорт уже выполнен; повторять его по материалам этого документа нельзя. Реальные данные, имена операторских файлов и идентификаторы не публикуем.

## 1. Для чего проводилась сверка

Цель состояла в выделении технических характеристик номенклатуры из неоднородных таблиц без переноса туда случайно попавших количеств, адресов оборудования и полей эксплуатации. В тот момент исходные таблицы рассматривались **только как примеры**, а не как готовая база или гарантия полноты справочника. Неоднозначные значения требовали ручного решения вместо автоматического слияния или догадки.

## 2. Наблюдения по исходным данным

| Раздел примеров | Что удалось установить | Какое ограничение выявлено |
|---|---|---|
| Оптические кабели | Тип волокна, разъёмы, исполнение, длина и число волокон являются характеристиками позиции. | Обозначения LC/MPO/LCHD, PC/UPC/APC, полярность и gender смешивались; по короткой записи нельзя всегда достоверно восстановить все свойства. |
| Кабели питания | Разъёмы A/B, длина, цвет, номинал и обозначение проводников описывают товар. | Четыре встреченных цвета не образуют полного справочника; направление разъёмов и запись жил требуют проверки человеком. |
| Медные патч-корды | Встречались RJ45–RJ45 UTP Cat 5e разной длины. | Они не являются ни оптическими, ни кабелями питания; тогда рассматривалась отдельная категория `copper_network_cable`. |
| SSD/HDD | В исходных строках различались тип диска, интерфейс, скорость, форм-фактор, маркетинговая ёмкость, бренд и модель. | Ёмкость из ОС не равна обязательно паспортной; часть ячеек форм-фактора Excel превратил в даты; `ATA` нельзя автоматически считать производителем. |
| Сетевые адаптеры | Прямых примеров NIC в предоставленных таблицах не было. | Отсутствие примеров не доказывает полноту словарей PCIe, media и port notation. |

Историческая идея отдельного `copper_network_cable`, полей `conductor_count`/`conductor_cross_section_mm2` и расширения SFP ENUM была **решением этапа проектирования**, а не обещанием, что такие поля существуют в нынешнем `LEAVES`. Текущая конфигурация категорий фиксирована кодом и не содержит `copper_network_cable`; не восстанавливаем эту старую категорию из документации автоматически.

### Историческое соответствие оптических примеров

Stage 5 рассматривал `product_type` для типа изделия, `fiber_mode` (`SM`/`MM`), `fiber_standard` (`OM2`/`OM3`/`OM4`), `connector_a/b`, `polish_a/b`, `fiber_count`, `length_m` и `polarity`. Эти **старые ключи** отражают исходный дизайн. Нынешний `optical_patch_cord` использует другие ключи, перечисленные в [CATALOG_SCHEMA.md](CATALOG_SCHEMA.md); переносить записи между версиями без явного mapping и миграции нельзя.

По маркировке `SM` нельзя автоматически выбирать `OS2`, по разъёму нельзя без подтверждения выводить полировку, а по описанию `Duplex`/`12F` — назначать число волокон, если спецификация неоднозначна. `length_m` в историческом дизайне трактовалась как десятичное число метров.

### Историческое соответствие кабелей питания

Тогда проверялись разъёмы CEE 7/7, IEC C13/C14, Type I, длина в метрах, цвет, ток и напряжение, иногда запись проводников вида `3×0.75 mm²`. Обсуждалось раздельное хранение номинальных тока/напряжения и параметров жил; источники не задавали исчерпывающий словарь цветов. Нынешняя `power_cable` использует `type`, `connector_a`, `connector_b`, `length_m`, `rating`, `color`; старые поля `rated_current_a`, `rated_voltage_v` и проводников **не** следует объявлять действующими только по этому протоколу.

### Историческое соответствие дисков

На этапе сверки предлагалось разделять SATA/SAS и скорость интерфейса, модель и заводской идентификатор, маркетинговую и фактически наблюдаемую ёмкость. Записи производителя и модели не разделяются автоматически по пробелам: в примерах встречались объединённые бренд, модель и несколько кодов. Текущие поля SSD/HDD и их фактические типы следует брать из исходного кода, а не из предполагаемых старых `capacity_bytes` или `interface_speed_mbps`.

## 3. Правила, которые остаются полезными

- Количество, размещение по серверу/стойке, IP, закупочный статус и факт установки **не являются** техническими характеристиками `Item`; их нельзя слепо импортировать в каталог.
- Неоднозначное значение оставляем для ручной идентификации. Нельзя вводить fuzzy merge или удалять дубликаты по одному похожему имени без проверенного идентификатора.
- Примеры из одной таблицы не задают полный допустимый vocabulary разъёмов, цветов, производителей или интерфейсов.
- Инженерская маркировка и паспортные характеристики имеют приоритет над догадками по Excel-ячейке.
- Факт проектного решения Stage 5 не равен действующему schema contract; изменения предметной модели проводим через версионированные миграции и регрессионные проверки.

## 4. Граница использования

Документ нужен, когда выясняем **почему** прежняя схема выбирала определённые поля или почему автоматический импорт был отклонён. Для разработки и ручного ввода используем текущую [схему каталога](CATALOG_SCHEMA.md), [требования](PRODUCT_REQUIREMENTS.md) и backend. Для production-импорта этот файл неприменим: первоначальный bootstrap завершён, обычные мутации остаются под отдельной защитой `REAL_INVENTORY_MUTATIONS_ENABLED=false` по последнему документированному состоянию.
