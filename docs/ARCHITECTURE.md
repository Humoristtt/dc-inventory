# Архитектура

## Назначение

Система предназначена для инвентаризации оборудования и расходных материалов ЦОД с полной прослеживаемостью движения остатков.

## Основной инвариант

Остаток оборудования нельзя изменять произвольным редактированием числа.

Любое изменение остатка должно происходить через складскую операцию:

- приход;
- выдача;
- возврат;
- перемещение;
- списание;
- корректировка.

Это позволяет восстановить полную историю состояния склада на любой момент времени.

## Режимы учёта

### Количественный

Используется для однородных позиций, где достаточно учитывать количество.

Примеры:

- кабели;
- массовые SFP;
- расходные материалы.

### Серийный

Используется для оборудования, которое необходимо отслеживать индивидуально.

Примеры:

- HDD/SSD;
- сетевые карты;
- дорогостоящие трансиверы;
- другое оборудование с S/N.

## Основные сущности

Планируются:

- User
- Category
- CategoryAttribute
- Item
- InventoryUnit
- Location
- StockBalance
- Movement
- MovementLine
- AuditEvent
- NotificationOutbox

Точная схема будет закреплена до первой бизнес-миграции базы данных.

## Компоненты

Планируемая схема:

Telegram Mini App
→ Cloudflare
→ Cloudflare Tunnel
→ Nginx
→ React / FastAPI
→ PostgreSQL

Отправка Telegram-уведомлений:

FastAPI / worker
→ Telegram Gateway
→ Telegram Bot API

## Безопасность

- Telegram initData обязательно проверяется backend.
- Клиентским Telegram-данным без серверной проверки доверять нельзя.
- PostgreSQL не публикуется в интернет.
- Production VM не имеет write-доступа к GitHub.
- Секреты не хранятся в Git.
- Складские операции должны быть транзакционными.
- Конкурентная выдача последней единицы товара должна быть защищена блокировками/атомарными проверками.
